# Canvas Landing Page — Design Specification

## 0. Purpose

This document reconstructs the visual system visible across the six supplied screenshots into an implementation-ready design specification.

The target is **not** a generic SaaS landing page. The visual identity is a deliberate combination of:

- hand-drawn editorial typography
- white/paper surfaces
- black ink-like outlines
- electric blue interaction accents
- pastel sticky-note colors
- dark navy grid sections
- imperfect rotation and taped-paper decoration
- product UI shown as a real artifact, not a generic 3D mockup
- restrained motion that feels physical and playful

**Important:** the screenshots are the source of truth. Measurements below are normalized implementation guidance inferred from the 1920×954 references. Exact font files and exact original CSS cannot be guaranteed from screenshots alone.

---

# 1. Visual Direction

### Keywords

`playful` · `handmade` · `editorial` · `collaborative` · `visual` · `bold` · `clean` · `slightly imperfect`

### Avoid

- glassmorphism
- excessive gradients
- neon cyberpunk effects
- giant floating 3D objects
- excessive rounded cards
- excessive shadows
- generic AI-generated SaaS illustrations
- excessive blur
- excessive animation
- perfectly symmetrical decorative elements

The design should look like a **real product team built a visual collaboration tool**, not like a template generated by an AI design system.

# 4. Hero

The hero is intentionally **editorial rather than product-dashboard-first**.

### Composition

Center stack:

1. small eyebrow: `VISUAL COLLABORATION TOOL`
2. oversized `CANVAS` display wordmark
3. short supporting paragraph
4. primary CTA + secondary CTA

Around the center are floating sticky notes:

- Real-time collaboration
- Templates
- Built for teams
- Infinite boards
- Present ideas visually

There are also thin hand-drawn arrows and a small vertical tool palette.

### Hero typography

The main `CANVAS` treatment is the strongest type element on the page.

Recommended:

- very large display font
- extremely heavy weight
- compressed/tight line-height
- slightly irregular/rounded letterforms
- black ink
- no gradient
- blue hand-drawn underline under the eyebrow/selected phrases

### Hero decoration

Sticky notes should never be perfectly horizontal.

Use:

- `-2deg` to `+2deg` rotation
- tiny vertical float
- paper shadow
- translucent gray tape strip
- pastel fill
- compact icon + label

Decorative arrows should look hand-drawn, with small irregular curvature.

# 12. Component Rules

## Buttons

Primary:

- electric blue fill
- near-black text
- 2px dark border
- subtle dark lower shadow
- 56px desktop height
- compact horizontal padding
- tiny arrow/icon may sit at the end

Hover:

- translateY(-2px)
- shadow becomes slightly deeper
- no scale-up larger than ~1.02

Secondary:

- white background
- 2px dark border
- dark text
- same height as primary

Text CTA:

- no box
- dark text
- blue hand-drawn underline

---

## Sticky Note

Required structure:

```text
┌───────────────┐
│     tape      │
├───────────────┤
│ icon  label   │
│       copy    │
└───────────────┘
```

Rules:

- pastel background
- 1–2px irregular rotation
- gray tape rectangle above top edge
- subtle paper shadow
- black icon/text
- avoid excessive border radius
- corners can remain nearly square

Suggested colors:

- mint `#A8EFCF`
- yellow `#FFEF9D`
- peach `#FFC4A6`
- pink `#F4A6CD`
- sky `#BCEEFF`
- lavender `#D7CBFF`

---

## Underline

The blue underline is a recurring brand device.

Do not use a standard browser `text-decoration` for hero headings.

Implement as:

- pseudo-element or SVG path you draw yourself
- electric blue
- ~4px
- slight rotation
- width approximately equal to emphasized phrase
- tiny movement allowed

---

## Hand-drawn Arrow

Build these yourself using:

- SVG `<path>`
- CSS transform
- Motion/GSAP if animated

Do not use Lottie.

The stroke should be:

- black on light sections
- muted blue/gray on dark sections
- ~2px
- rounded linecap/linejoin

# 13. Grid Background

Use CSS rather than an image.

Example concept:

```css
background-image:
  linear-gradient(var(--grid-color) 1px, transparent 1px),
  linear-gradient(90deg, var(--grid-color) 1px, transparent 1px);
background-size: 24px 24px;
```

Light grid:

`rgba(12,28,48,0.065)`

Dark grid:

`rgba(255,255,255,0.055)`

Keep it extremely subtle.

# 14. Motion System

The motion should reinforce the handmade identity.

## Always-on loops

These are suitable for CSS keyframes or a small JS animation library.

### Sticky note float

```text
0%    translateY(0) rotate(-1deg)
50%   translateY(-7px) rotate(1deg)
100%  translateY(0) rotate(-1deg)
```

Duration: `4.5s`

Loop: infinite

### Arrow wiggle

```text
0%    rotate(0) translateX(0)
50%   rotate(-4deg) translateX(4px)
100%  rotate(0) translateX(0)
```

Duration: `2.8s`

### Underline drift

```text
0%    translateX(0) scaleX(1)
50%   translateX(3px) scaleX(1.04)
100%  translateX(0) scaleX(1)
```

Duration: `3.6s`

### Small accent bob

```text
0%    translateY(0) rotate(0)
50%   translateY(-10px) rotate(2deg)
100%  translateY(0) rotate(0)
```

Duration: `5s`

Use different negative delays for multiple decorative elements so they do not synchronize.

Example:

```css
.note:nth-child(1) { animation-delay: -0.8s; }
.note:nth-child(2) { animation-delay: -2.1s; }
.note:nth-child(3) { animation-delay: -3.4s; }
```

---

# 15. Scroll Animation System

Do not animate every element.

Recommended reveal pattern:

```text
initial:
opacity 0
translateY 36px

visible:
opacity 1
translateY 0
```

Duration: ~700ms.

Stagger:

`80–120ms`

Use scroll animation for:

- section headings
- feature cards
- how-it-works cards
- template cards
- product preview
- testimonial
- CTA decorations

Avoid:

- aggressive 3D rotation
- large zoom
- long flying entrances
- constant scroll-jacking
- animation on every text line

---

# 16. Recommended Animation Architecture

## Preferred for React: Motion

Use the `motion` package for:

- enter/exit animation
- `whileInView`
- `useScroll`
- parallax
- spring movement
- SVG path animation
- stagger
- hover/tap interaction

Install:

```bash
npm install motion
```

Useful primitives:

```text
animate()
inView()
scroll()
stagger()
spring()
```

For React:

```text
motion.div
whileInView
useScroll
useTransform
```

This is the best fit when the site is already React/Next.js and the animation language should stay close to components.

---

## Preferred for complex timeline work: GSAP + ScrollTrigger

Use GSAP when you need:

- precise timeline choreography
- pinned sections
- scrubbed animations
- complex SVG drawing
- sequencing multiple decorative elements
- advanced scroll storytelling

Install:

```bash
npm install gsap
```

Use:

```text
gsap.timeline()
ScrollTrigger
```

Do not introduce GSAP everywhere if Motion/CSS is enough.

---

## Use CSS for simple infinite loops

For:

- sticky-note bob
- tiny arrow wiggle
- underline drift
- cursor float
- small decorative movement

CSS `@keyframes` is preferable.

It is smaller, simpler, and easier to maintain.

---

## Optional smooth scrolling

A smooth-scroll library can be used if the overall experience needs a more fluid canvas-like feel.

Use it carefully. Native browser scrolling should remain the default if the page does not benefit from scroll interpolation.

---

# 17. Animation Accessibility

Always implement:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

For JS animation systems:

- do not start decorative infinite loops when reduced motion is enabled
- replace parallax with static positioning
- keep content immediately visible
- never make information depend on animation

# 18. Responsive Behavior

## 1024px and below

- reduce hero display size
- reduce sticky-note count
- feature grid can remain 2 columns
- reduce product preview scale
- template grid = 2 columns
- simplify footer columns

## 768px and below

- nav collapses
- hero becomes single column
- decorative sticky notes move farther away or are hidden selectively
- feature cards = 1 column
- how-it-works = 1 column
- directional arrows become vertical
- template grid = 1 column
- product preview should become horizontally scrollable or transform into a simplified mobile UI
- CTA buttons may stack

## Small mobile

Prioritize:

1. headline
2. supporting copy
3. CTA
4. product proof
5. features

Decorative elements should never reduce readability.

# 20. Shadows

Shadows are subtle.

Use mostly:

```text
0 8px 28px rgba(5,9,20,.08)
0 10px 30px rgba(5,9,20,.10)
```

For the product preview/testimonial, a slightly more physical lower shadow is acceptable.

Avoid huge blurred shadows.

The visual language should feel like **paper sitting on a desk**, not floating glass.

# 21. Iconography

Icons should be:

- simple
- bold enough at small sizes
- black/ink
- mostly 2px stroke or compact filled glyphs
- rounded where appropriate

Use icon containers in feature cards:

- ~42–48px
- pastel background
- subtle border
- 8–12px radius

Do not use colorful gradient icon libraries.

# 22. Decorative Asset Strategy — No Lottie

The supplied design clearly relies on animated-looking decorative elements such as:

- arrows
- underline strokes
- cursor movement
- sticky-note floating
- small accent movement

Do **not** use Lottie.

Build them from primitives:

### SVG

Best for:

- hand-drawn arrows
- underline strokes
- curved connectors
- stars
- doodles

Animate:

- `stroke-dashoffset`
- `stroke-dasharray`
- `transform`
- `opacity`

### CSS

Best for:

- float
- bob
- rotate
- wiggle
- tape movement
- simple looping decoration

### Motion / GSAP

Best for:

- scroll-linked motion
- stagger
- coordinated sequences
- complex SVG path animation
- timeline choreography

The source asset should remain a simple SVG/HTML/CSS element, not a pre-rendered animation file.

# 25. Engineering Rules

1. Keep colors centralized in `canvas-design-tokens.json`.
2. Never hardcode pastel colors inside individual components.
3. Keep animation durations/easing centralized.
4. Prefer CSS transforms over changing `top`, `left`, `width`, or `height` during animation.
5. Avoid unnecessary scroll listeners; use IntersectionObserver/Motion/ScrollTrigger.
6. Use GPU-friendly `transform` and `opacity`.
7. Decorative animation must never block interaction.
8. All infinite animations need a reduced-motion fallback.
9. Do not make every card animate independently in a distracting way.
10. Preserve the intentionally imperfect rotations.
11. Do not replace the hand-drawn visual language with polished enterprise SaaS UI.
12. Keep product screenshots crisp and readable.
13. Avoid excessive rounded corners; only major cards use large radii.
14. Use whitespace aggressively around major headings.
15. Blue should be an accent, not the page background.

# 27. Final Design Principle

The most important rule is:

> **Make it feel like a real, physical creative workspace translated into the browser.**

The interface should have enough structure to feel professional, but enough imperfection to feel human.

The combination of **black ink + electric blue + paper white + pastel notes + dark grid + hand-drawn motion** is the core identity and should remain consistent across every section.
